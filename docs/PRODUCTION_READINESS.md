## Not Yet Implemented (remaining MUSTs)

- **On-chain executor finality + nonce management per chain**: required once on-chain action adapters exist.
- **Deployment wiring**: ensure deployments ship verifier-trusted `registry_state` checkpoints/manifests and all verifiers execute `ValidDecision(bundle, registry_state)` (not raw image-id verification). Helpful tooling exists:
  - `mprd deploy check-bundle` validates a production bundle (signed registry checkpoint + signed manifest + local policy artifacts).
  - `crates/mprd-zk/src/lib.rs` provides registry-bound attestor+verifier constructors for `mpb-v1` and `tau_compiled_v1`.
- **Owner namespace / node assignment / admission tiering**: the runtime still lacks first-class `namespace_id`, per-node namespace assignment, activation epochs, and certification-tier gates. Current authority is pseudonymous key or committee material, not yet a full Tau-owner namespace model.
- **Execution-time governance bridge refinement**: the local formal packet now proves execution-time `governance_ok` should require both a resolved policy and an admitted governance update, the runtime now shares one constructor-gated governance admission rule between core prepared-state rails and concrete `mprd-zk` governance gate packets, and the live `attest_ready -> verify -> execute_ready` path now fails closed if attestors omit or drift the admitted governance metadata. `mprd-zk` now also provides a concrete helper that rebuilds `ExecutionReadyBundle` from a verifier-trusted registry authorization provider plus an optional concrete `GovernanceGateInput`, plus a sibling helper that executes through the real `execute_ready(...)` boundary on top of that same bridge; both fail closed if registry attestation metadata drifts, if the exact signed registry checkpoint binding drifts on the signed-registry path, or if the gate input disagrees with the state-prepared rails. The shipped production `mprd serve` path now injects that bridge into the orchestrator before side effects happen, the local CLI executor wrappers forward `execute_ready(...)` instead of dropping back to raw `execute(ready.verified())`, and the serve bridge now explicitly rejects any governance witness unless a concrete gate packet is available on that path. The remaining gap is still the replayable refinement edge from concrete registry and governance objects into the live execution authorization packet as one top-level theorem.
